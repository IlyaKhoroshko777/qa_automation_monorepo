## Крок 3. DOM-дерево карток рецептів: три питання і комбінатор

### Чекліст читання дерева

**Елемент або блок:** кнопка збереження рецепта  
**Сторінка:** головна сторінка, список рецептів

1. **Скільки однакових сусідів має елемент?**  
   11 — всього на сторінці 12 кнопок `Save recipe`, тому для конкретної кнопки існує ще 11 аналогічних.

2. **Найближчий унікальний предок:**  
   Унікального предка за атрибутом немає.  
   `article` використовується як контейнер картки, а конкретну картку можна відрізнити за унікальним текстом назви рецепта.

3. **Пряма дитина предка чи глибший нащадок?**  
   Глибший нащадок `article`.

4. **Форма дерева:**  
   Список однакових карток + вкладена картка.

5. **Потрібне звуження через фільтр за змістом?**  
   Так.

**Висновок — комбінатор або патерн:**  
`article → фільтр за назвою рецепта → кнопка Save recipe всередині картки`

### Перевірка комбінаторів

| Пара | Перевірка в Console | Результат | Висновок |
| --- | --- | ---: | --- |
| `article → назва рецепта` | `document.querySelectorAll('article > ._title_savzh_65').length` | 0 | `>` не підходить, оскільки назва рецепта не є прямою дитиною `article`. |
| `article → назва рецепта` | `document.querySelectorAll('article ._title_savzh_65').length` | 12 | Пробіл підходить, оскільки назва рецепта є глибшим нащадком `article`. |
| `article → Save recipe` | `document.querySelectorAll('article > button[aria-label="Save recipe"]').length` | 0 | `>` не підходить, оскільки кнопка не є прямою дитиною `article`. |
| `article → Save recipe` | `document.querySelectorAll('article button[aria-label="Save recipe"]').length` | 12 | Пробіл підходить, оскільки кнопка є глибшим нащадком `article`. |

Для обох пар використовується комбінатор-нащадок — пробіл, тому що і назва рецепта, і кнопка `Save recipe` знаходяться глибше всередині `article`, а не безпосередньо на один рівень нижче.

## Крок 4. DevTools-діагностика: сценарій «неправильний пароль»

### Чекліст DevTools перед тестом

**Сторінка або сценарій:** сторінка логіну, валідний email + неправильний пароль

1. **Сценарій відтворено вручну до потрібного стану:**  
   `[так]`

   Введено валідний email, неправильний пароль і натиснуто кнопку `Login`.

2. **Стан елемента в Elements:**  
   До submit повідомлення про помилку відсутнє в DOM.  
   Після submit форми воно динамічно з'являється в DOM, а через декілька секунд зникає.

3. **Console вище рядка введення:**  
   `[так]`

   Після невдалого логіну з'являється червоний запис:

   `POST 400 (Bad Request)`

4. **Локатор перевірено на унікальність:**  
   `[так]`

   У момент, коли повідомлення про помилку видиме:

   `$$('[role="alert"]').length` → `1`

   Після зникнення повідомлення:

   `$$('[role="alert"]').length` → `0`

5. **Network:**  
   Status: `400`  
   Time: `48 ms`

6. **Умова появи елемента записана поруч із селектором:**  
   `[так]`

   **CSS-селектор:**  
   `[role="alert"]`

   **Умова появи:**  
   Елемент з'являється після submit форми логіну з валідним email та неправильним паролем.

### Додаткове спостереження

Toast має динамічний `id`, значення якого збільшується при кожному новому повідомленні (`1 → 2 → 3 ...`).

Тому `id` не використовується як стабільний локатор для цього елемента.

### Висновок

- `[так]` готово для тесту
- `[ні]` баг застосунку
- `[ні]` потрібен інший локатор

## Крок 5. CSS-селектори реєстрації: атрибути, комбінатори, псевдокласи

### Атрибутний селектор для password

Перевірка:

`$$('input[type="password"]').length` → `2`

Селектор `input[type="password"]` знаходить два поля пароля, тому він неоднозначний.

Звуження до конкретного поля:

`$$('#password').length` → `1`

Пошук звужено до одного конкретного поля через унікальний `id="password"`.

### Комбінатор прямого нащадка

Перевірка:

`$$('label > #terms').length` → `1`

Checkbox `#terms` є прямою дитиною `label`, тому використовується комбінатор `>`.

### Комбінатор сусіда

Перевірка:

`$$('#terms + span').length` → `1`

Елемент `span` знаходиться одразу після checkbox `#terms` на тому самому рівні DOM, тому використовується комбінатор `+`.

### Псевдоклас `:checked`

До кліку по checkbox:

`$$('#terms:checked').length` → `0`

Після кліку по checkbox:

`$$('#terms:checked').length` → `1`

Псевдоклас `:checked` знаходить checkbox лише тоді, коли він перебуває у вибраному стані.

### Псевдоклас `:disabled`

На головній сторінці до відкриття панелі фільтрів:

`$$('button:disabled').length` → `1`

Після відкриття панелі фільтрів:

`$$('button:disabled').length` → `2`

Неактивними є:

- кнопка `Reset filters`;
- кнопка переходу на попередню сторінку.

Звуження вибірки до кнопки попередньої сторінки:

`$$('[aria-label="previous page"]:disabled').length` → `1`

Селектор `[aria-label="previous page"]:disabled` знаходить одну конкретну неактивну кнопку переходу на попередню сторінку.
